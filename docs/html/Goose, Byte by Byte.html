Goose, Byte by Byte

An unofficial introduction · Goose v2026.3

Goose

476f6f7365top

A memory-safe systems language with no heap, no garbage collector and no lifetime annotations.

Every growable value lives on one of a few data stacks, counted when the program compiles. Each stack holds at most one growing value, always on top, so growing it is a pointer bump that never moves anything. Leaving a scope frees everything it built with one store.

var words: u8[][>..] = [];
for i in 5 { words.push(str("word", i)); }
C++
vector<string> keeps a 24 to 32-byte string object per element. Longer strings allocate on their own, and every element is destroyed one by one.
Rust
Vec<String> keeps a 24-byte header per string and allocates every string separately, so these five words are six blocks to allocate and free.

Arrays are chosen by what their size does

Tutorial §5

There is no single array type. Every kind below except the slice is its metadata followed by its elements, inline and packed, with no pointer to a separate block. A slice is a view into one of the others.

The last line of each tile names the closest equivalent in C, C++ or Rust.

Strings are u8 arrays. u8[>..] builds one, u8[] stores a finished one, u8[..16] fits a short one inside a struct, and u8[:] views someone else's bytes.

References stay valid, and the compiler proves it

Tutorial §4

Growing never moves anything

var items: Item[>..] = [];
let first .= items.push(Item { 1, 0.5 });       // a reference to element 0
for i: i32 in 2..1000001 { items.push(Item { i, 0.0 }); }
first.weight = 99.5;                            // still valid
print(items.len, " items, first is ", items[0]);
1000000 items, first is Item { 1, 99.5 }

push returns a reference to the new element. A vector or Vec may reallocate as it grows, so C++ and Rust can't promise this. The Rust versions of the repository's benchmarks use integer indices instead.

C++
A reference into a vector dangles once push_back reallocates, which is undefined behaviour. Keeping one safely takes reserve() up front or a deque.
Rust
The borrow checker rejects &v[0] held across v.push() (error E0502), so code keeps an index instead.

Safety without annotations

struct Node { v: i64, left: Node? }

fn main() {
    var root = Node { v: 1, .. };
    {
        var child = Node { v: 2, .. };
        root.left .= child;          // child ends at the next brace
    }
}
demo.goose:7: error: storing a reference rooted at child, which does not outlive the destination (§9.2)

There is no lifetime syntax, no borrow rules and no unsafe. The compiler infers what every reference is rooted in and rejects one that could outlive its owner. Two references to the same thing are fine.

C / C++
This compiles, and root.left dangles as soon as the scope holding child ends.
Rust
Rejected as well, but a struct that holds a reference needs a lifetime parameter, as in struct Node<'a>, and so does every type that contains it.

No null dereferences

struct Node { key: i32, left: Node? }

fn main() {
    var a = Node { key: 1, .. };
    let n = a.left;                   // a Node? may be null
    if n { print(n.key); }            // inside the if, n is a Node&
    print(n.key);                     // outside it, n is unchecked
}
null.goose:7: error: optional value must be narrowed (if/guard/assert) before use

A reference is never null unless its type says so. A Node? must be checked by if, guard or assert before use, and inside the check it is a plain reference. Using one unchecked is a compile error, so there is no null pointer to dereference at run time.

C / C++
Any pointer can be null, and dereferencing one is undefined behaviour, usually a crash.
Rust
Option<&T> is the same idea, opened with match, if let or unwrap().

Integers do what the source says

fn main() {
    let a: u8 = 200;
    let b: u8 = 100;
    print(a + b);                 // an 8-bit add: wraps to 44
    print(-7 % 3);                // % is Euclidean: 2
    var big: i32 = 2147483647;
    big += 1;                     // signed overflow
    print(big);
}

Arithmetic happens at the operands' own width, so u8 + u8 is an 8-bit add. Narrower types widen on their own, nothing narrows without as, and mixing u32 with i32 is a compile error until you say which you meant. Unsigned arithmetic wraps by definition. Signed overflow aborts in a debug build and wraps in release, so it is never undefined. % is Euclidean, so x % n is always a valid index into an array of length n, and dividing by zero always aborts.

fn main() {
    let x: u32 = 1;
    let y: i32 = 2;
    print(x + y);
}
mixed.goose:4: error: operands of + have no common type: u32 and i32 (convert one with `as`)
C / C++
Signed overflow is undefined behaviour, which optimizers assume never happens. A uint8_t 200 + 100 is promoted to the int 300, mixed signed and unsigned operands convert silently, and -7 % 3 is -1.
Rust
Overflow panics in a debug build and wraps in release. Nothing widens on its own, and -7 % 3 is -1, with rem_euclid giving 2.

Links and enums sized to what they hold

Tutorial §9 and §10

A tree node with two links is 12 bytes

Links are 4-byte offsets within the node's own array, and 0 means null. Nothing in the tree is an address, so saving it writes its bytes, and loading checks every link before the tree is used.

C++
A unique_ptr<Node> node is 24 bytes, plus a heap allocation and an allocator header for each one.
Rust
Box<Node> is also 24 bytes plus an allocation. An index arena gets 4-byte links, but they are untyped and go stale silently when slots are reused.

Fixed mode can be indexed and overwritten with another variant. Variable mode packs values end to end, so the array is walked instead of indexed, and you may point into a payload.

C++
std::variant<Circle, Rect, Dot> is 24 bytes per value, 72 for these three.
Rust
The same enum is also 24 bytes per value. Every element pays for the largest variant plus padding.

Where the speed comes from

Tutorial §17

Goose compiles to C, so a C programmer could write any of this by hand. The difference is that Goose makes these layouts the default and checks them for safety. Against C++ that already uses arenas and flat offsets, the lead narrows to 1.26×.

Growing is a pointer bump

There is no malloc, no capacity check and no copy on growth, so a reference into a growing array stays valid.

Freeing is one store

No destructor runs when a scope ends. The stack top moves back, however many nodes the structure holds.

Records are one contiguous block

Strings, lists and records nest inline with no pointers between them, so a scan streams straight through memory.

Values are built where they land

A value is constructed at its final destination through any depth of calls, so returning a growable array by value costs nothing.

Enums cost what each value holds

A leaf and a branch each take their own size, and case functions dispatch through a jump table on the tag.

Links of 1, 2 or 4 bytes

A relative reference stores a typed link as a small offset instead of an 8-byte pointer, so more of a structure fits in cache.

Bounds checks proven away

Every index is checked unless the compiler proves it safe. An index type such as u32 in dist is validated once, when it is stored, and checkfree rejects a loop that still has a check.

Direct calls, inlined on request

Function values exist only at compile time, so every call is direct and higher-order code compiles to the loop it looks like. inline fn inlines a function at every call, whatever its size, and asks the C compiler to when Goose cannot do it itself. simd fn adds AVX2 and AVX-512 versions and runs the widest one the CPU has.

let evens = xs.filter() { it % 2 == 0 };     // one loop, writing into evens
inline fn lerp(a: f64, b: f64, t: f64) -> f64 { a + (b - a) * t }
simd fn encode(out: u8[>..]&, src: u8[:]) { ... }
C / C++
inline is mostly about linkage. Forcing it takes __forceinline or always_inline, which differ by compiler, and std::function and virtual calls stay indirect.
Rust
#[inline(always)] is the closest match. Closures passed as generics inline the same way, while Box<dyn Fn> stays indirect.

Also in the box

Tutorial §12 to §16

Errors that return from a distance

guard ok else { return [], str("bad age: ", line) from load; }

Returns straight out of load, however many calls deep. The compiler checks every use, so there is no unwinder, no exception and no Result type.

C++
Exceptions need an unwinder and unwind tables, and any call might throw.
Rust
A Result travels up through ? at every call in between.

Threads that share nothing

thread_fn worker() {
    let job = qget<Job>();      // blocks on the Job queue
}

Each worker is compiled as its own program with its own memory. Values cross typed queues as a memcpy, so data races, locks and atomics do not exist. A contained worker that aborts ends alone, and the program carries on.

C++
Threads share memory, so correctness rests on locks, atomics and memory orderings.
Rust
Sharing is checked through Send, Sync and Mutex, but it is still shared memory.

Pools for lifetimes that don't nest

reusable var pool: Item[>..] = [];
let s0 = pool.alloc_index(Item { 10, 1.0 });
pool.free(s0);                                  // the slot goes on a freelist
let s1 = pool.alloc_index(Item { 11, 2.0 });    // and is handed out again

Caches, graphs and anything deleted in any order live in a reusable pool, which hands out slots and takes them back. A stale slot reads another valid value of the right type, never freed memory.

C / C++
A stale pointer into a recycled slot is undefined behaviour, and may see another type or freed memory.
Rust
The slotmap crate catches stale keys with a generation counter, which Goose leaves to you.

Saving is writing bytes

var image: u8[>..] = tree.to_bytes();
var loaded, ok = from_bytes<Node[>..]>(image);   // every link checked first

A structure linked by relative references means the same thing at any address. Saving it writes its bytes, and loading verifies every tag, length and link, so a corrupt file is a false, never a wild reference.

C++ · Rust
Pointers mean nothing on disk, so data goes through a serializer such as protobuf or serde, or through unsafe casts.

Code generated per field or variant

fn visit_fields<T, F>(value: T&) {
    const for <N, A> in fields<T> { F(N, &value.A); }
}

const for repeats code once for each field of a struct, variant of an enum or listed type, at compile time. Serializers and visitors need no reflection at run time.

Rust
Derive macros do the same, written as separate procedural-macro crates.
C++
Usually macros or hand-written visitors.

Plain C in, plain C out

// C, called from Goose
extern fn hypot(x: f64, y: f64) -> f64;
// Goose, called from C
export "c_add" fn add(a: i32, b: i32) -> i32 { a + b }

A whole program compiles to one C file and calls C directly. export fn goes the other way, so Goose can be a library inside a C or C++ program. The bundled TinyCC runs a program in-process with no build step.

C++
extern "C" works in both directions.
Rust
Calling C needs an unsafe extern block, and exporting needs no_mangle with extern "C".

The project

Apache 2.0 licensed. Designed by Wouter van Oortmerssen, who also created the Lobster language. The README says the compiler, about 30,000 lines of C++, was written almost entirely by Claude Fable from his design. CI runs the test suite on Windows, macOS and Linux, plus a sanitizer job.

What it asks of you

Tutorial §18

You decide where data lives

Usually the function that builds a value owns it. When lifetimes don't nest, you use a reusable pool.

Recursion takes its storage as a parameter

A recursive function can't keep growable data across its recursive call, so it is passed a pool or a builder.

Variable-size elements are walked, not indexed

An array of variable-size records is sequential, unless you keep an index of references beside it.

No escaping closures or function pointers

Function values exist only at compile time, dispatch is by enum tag, and the whole program compiles at once.

Freed pool slots can go stale

A slot you gave back and still name reads whatever reuses it. That is a logic bug to avoid, never memory corruption.

It is new

The specification is a draft and changes most weeks. Prebuilt releases started in October 2026.
